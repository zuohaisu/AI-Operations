# 2026-08-18

## DeepSeek Harness (dsh) 调研 + 安装（Engine 执行器候选评估）

- 调研结论：dsh v0.1（当前 npm 实际 0.1.0-rc.7，MIT）是"一切皆插件"的 agent harness，官方仅内置 **web + headless** 两个 profile；终端交互 TUI 需社区插件。
- 用户使用场景确认：**放进 stablyai/orca 编排器**（多 agent 编排，支持任何终端可跑的 CLI agent）→ 选 **dsh-tui**（Claude Code 风格 TUI，交互式，适配 Orca 的 terminal create/wait tui-idle 驱动模型）；headless 留给 Engine YAML script 节点。
- 两个 TUI 候选：`@deepseek-harness-tui/dsh-tui` v0.8.0（Ink/React，3.19MB，Claude Code 风格，推荐）vs `deepseek-harness-tui` v0.3.0（Rust/ratatui，1.55MB，JSON-RPC 客户端，更轻但多一层进程）。
- **安装坑（重要）**：npm 10.9.7/10.9.8 的 arborist 在解析 dsh-tui 依赖时崩溃（`Cannot read properties of null (reading 'children')`，dsh 要 dsh-agent rc.7、dsh-tui 要 rc.6，全局顶层冲突）；`--force`/`--install-strategy=nested`/调换顺序均无效。**成功路径 = bun 全局安装**：`bun add -g @deepseek-ai/dsh @deepseek-harness-tui/dsh-tui`，然后 `bun pm -g trust koffi @deepseek-ai/dsh-subprocess-local @google/genai protobufjs`（4 个原生 postinstall 默认被 bun 拦截），再软链 `~/.bun/bin/{dsh,dsh-tui}` → `~/.local/bin/`。
- 当前状态：dsh 0.1.0-rc.7 ✅ 可用；dsh-tui 已装+软链，但首次初始化被残留目录 `.../lib/node_modules/@deepseek-ai/.dsh-CVmGGLec`（307MB npm staging 垃圾）阻塞——WorkBuddy 沙箱批量删除守卫拦截，需用户在**自己的终端**手动删：`rm -rf /Users/hzuo/.workbuddy/binaries/node/versions/22.22.2/lib/node_modules/@deepseek-ai/.dsh-CVmGGLec` 后重跑 `dsh-tui`。
