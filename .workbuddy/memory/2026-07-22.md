## 研究：AI-Operations 项目 + Start Prompt 比较方法

- 项目定位：建设「海粟通用 AI Agent 操作系统提示词（Start Prompt）」。真源 = `core/`（8 段）+ `modules/`（6 任务模块）；发布构建 v4（单文件 ~215 行）与 v5（由 `build_v5.py` 从顶层源重建 ~297 行）；`platform/` 是按工具分发的 delta。
- 现有对比实验 `eval/Benchmark-02`：冻结式、可复现、多模型（4 个）、双盲判分、3 arm（bare/v4/v5）、Wilson 区间裁决、holdout 防过拟合、judge 校准 + 人工审计。已很扎实。
- 关键可复现性事实：`eval/prompts/v5_core` 与 `v5_modules` 是顶层 `core/`、`modules/` 的逐字节副本；`build_v5.py` 实际从**顶层源**读，改顶层源后必须重跑 `build_v5.py`。
- 交付物：`01 Working/Start_Prompt_比较方法研究.md` —— 通用方法 SPCM（9 层）：把「比什么维度/用例/判分」与「具体哪几个 prompt」解耦，并提出 8 条在现有 `eval/` 上的落地改造（泛化 arms、多 judge、定性轨道、agentic 验证、扩用例库、dev-loop profile、跨模型聚合、成本进判据）。
- 现有 eval 相对「对比任意 start prompt」的 9 个缺口已记录在报告中（被 v4/v5 写死、单 judge、开放文本质量 out of scope、纯文本无工具执行、用例窄、维度耦合代码、缺迭代回路、跨模型聚合未固化、成本-质量 Pareto 缺失）。
