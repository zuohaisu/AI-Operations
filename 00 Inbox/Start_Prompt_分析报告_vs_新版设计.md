## 二、优点总结

### 2.1 你 Start Prompt 的核心竞争力（不可丢掉）

1. **Persona 设计极高** — 每个 Prompt 的角色感比 99% 的公开 Prompt 都强
2. **思维规则 > 任务指令** — 教 AI "怎么思考"比"做什么"更有复用价值
3. **反向指令具体可执行** — 不是"不要犯错"，而是"不要做XXX具体事"
4. **输出格式模板化** — 预设结构降低每次交互成本
5. **风险护栏硬** — 边界清晰、不可妥协

### 2.2 各文件独特亮点

| 亮点 | 来源 |
|------|------|
| SOP化做到极致（任务→格式映射+Checklist+模板库） | 365玩卡 |
| 五段式输出（结论→判断→行动→风险→何时找人） | Personal Samuel |
| 元认知层（Session Setup + 记忆系统 + 分层搜索） | Haisu v3.1 |
| 上下文模式分级（Active/Hot/Warm/Cold） | AGENT_OPERATING |
| Devplan→Implementation→QA→Deploy 完整流程 | Software PM Agent |
| Kill line + 数学透明 + Pace Check | Alfred |
| "挑战我的framing" + "找高杠杆点" | Build |
| 结构优先于安慰 + 方法论沉淀意识 | 海粟 |

## 三、缺点总结

### 3.1 致命问题

| 问题 | 影响 | 严重度 |
|------|------|--------|
| **长度失控** | 多个 700+ 行，Agent 工具 context window 被大量消耗 | 🔴 高 |
| **模块不统一** | 9个文件9种结构，无法互相对照和维护 | 🔴 高 |
| **Evismart 特定信息** | 大量失效内容（人员、CC编号、数据库名） | 🔴 高 |

### 3.2 缺失项

| 缺失 | 为什么重要 |
|------|-----------|
| **Agent 工具使用指导** | Cursor/Claude Code 有文件读写、终端、网络等工具，但你的历史 Prompt 都没告诉 AI 怎么用 |
| **自主 vs 确认的边界** | 工具型 Agent 需要知道什么可自主执行、什么必须先问 |
| **上下文分层加载策略** | 只在 AGENT_OPERATING 里有，但太工程化，没融入你的思维风格 |
| **复杂度自适应** | 简单任务不需要复杂规划，但你的长 Prompt 容易让 Agent 过度规划 |
| **统一的记忆沉淀机制** | 只有 Haisu v3.1 有，且绑定 Evismart 的 Nowledge Mem |

## 四、v4 设计原则

基于以上分析，v4 的设计遵循以下原则：

| 原则 | 说明 |
|------|------|
| **浓缩精华** | 把所有亮点浓缩到 ~200 行，控制在 context window 的 5-10% |
| **保留 Persona** | 海粟的身份、思维风格、价值观完整保留 |
| **保留思维规则** | "如何思考"是核心，不可删减 |
| **保留反向指令** | 具体可执行的 Anti-instructions |
| **新增 Agent 行为规则** | 自主 vs 确认的边界、工具使用指导、上下文加载策略 |
| **统一模块结构** | 9 个模块（§0-§9），清晰可维护 |
| **项目无关** | 去掉所有 Evismart 和特定项目细节 |
| **多工具兼容** | 适用于 Claude Code / Codex / WorkBuddy / Cursor / Qoder / Trae / Hermes |

## 六、使用建议

1. **基础用法：** 将 `Haisu_Universal_Start_Prompt_v4.md` 设为各 AI Agent 工具的默认 System Prompt / Start Prompt
2. **项目叠加：** 当进入具体项目时，额外加载项目级 CLAUDE.md / AGENTS.md / .cursorrules，v4 作为底层不变
3. **定期迭代：** 每 1-2 个月根据实际使用体验微调，特别是 §3（思维规则）和 §8（反向指令）
4. **按需扩缩：** 如果某工具 context window 紧张（如 128K 以下），可去掉 §7（工具使用指南）；如果某工具需要更多领域知识，可在 §1 后追加项目背景
